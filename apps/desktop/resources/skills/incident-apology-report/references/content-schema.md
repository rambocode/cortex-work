# content.json 字段说明

`scripts/generate_report.py` 的输入是一个 JSON 文件，结构如下。撰写时把内容填进这个结构即可，排版交给脚本。

```json
{
  "title": "关于7月22日平台服务中断的情况说明及致歉报告",
  "doc_number": "编号：YJ-2026-003",
  "salutation": "尊敬的客户：",
  "opening": "首先，对本次系统故障给贵司业务带来的影响，我们深表歉意。现将有关情况说明如下：",
  "sections": [
    {
      "heading": "事件概述",
      "paragraphs": ["2026年7月22日23时05分至23日1时10分，……"]
    },
    {
      "heading": "影响范围",
      "paragraphs": ["……"],
      "items": ["平台网页端及App无法访问；", "报警短信延迟发送。"]
    },
    {
      "heading": "处理过程",
      "paragraphs": ["本次事件的处理过程如下："],
      "timeline": [
        {"time": "7月22日 23:05", "event": "监控系统告警，运维人员立即介入排查。"},
        {"time": "7月23日 01:10", "event": "服务恢复正常，确认各项功能可用。"}
      ]
    }
  ],
  "signature": {
    "company": "示例科技有限公司",
    "extra": ["客服热线：400-000-0000", "邮箱：service@example.com"],
    "date": "2026年7月23日"
  }
}
```

## 字段说明

| 字段 | 必填 | 说明 |
|------|------|------|
| `title` | 是 | 报告标题，居中显示。建议格式："关于×××的情况说明及致歉报告" |
| `doc_number` | 否 | 文件编号，标题下方右对齐显示。没有就省略该字段 |
| `salutation` | 是 | 称呼，如"尊敬的客户："（全体）或"尊敬的×××有限公司："（具体客户） |
| `opening` | 是 | 称呼后的首段（致歉 + 引入） |
| `sections` | 是 | 章节数组，脚本自动编号"一、二、三……"。每节可含 `heading`（必填）、`paragraphs`（段落数组）、`items`（自动编号 1. 2. 3. 的条目，用于改进措施等）、`timeline`（渲染为"时间/处理情况"两列表格） |
| `signature` | 是 | 落款：`company` 公司名，`extra` 联系方式等附加行，`date` 日期。整块右对齐 |

## 注意

- 段落文字不要自带首行缩进空格，脚本会统一设置首行缩进 2 字符。
- `items` 不要自己写"1."编号，脚本会加。
- **上例中的 `signature` 是示例值，不是默认值**：`示例科技有限公司` / `400-000-0000` / `service@example.com` 绝不能出现在交付件里。真实的公司全称与联系方式按 SKILL.md 第 2 步确认（上下文里有就取用，没有就问用户）。
- 交付件里同样不允许出现 `【公司名称】`、`【客服热线】` 这类占位符——除非无人值守且确实问不到，此时必须在交付说明里逐条列出待替换项。
- `signature.date` 使用本次报告落款日期，通常为事件日期或用户指定日期。
- 简洁版就是 sections 少一些（事件说明/原因/致歉与承诺），结构不变。

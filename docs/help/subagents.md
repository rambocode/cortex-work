# 使用子代理

个人工作区最右侧现在有一条常驻工具栏。点击机器人图标即可打开“子代理”面板；再次点击同一图标会收起面板。

## 开始使用

无需打开功能开关。主 Agent 默认可以使用子代理：实质性任务在受益于专项能力、独立复核或并行调查时会主动委派；琐碎任务仍会直接完成。

分析仓库结构、定位代码路径或理解项目行为时，主 Agent 会优先调用只读的 Repository Explorer。复杂问题会先枚举产品定位、后端或核心实现、前端交互、测试与完成度等适用证据面，再按互不重叠的范围动态拆分并行执行。拆分数量取决于问题本身，因此像“分析当前项目主要解决什么问题”这类宽泛项目分析通常会出现多张并行子代理卡，而不是固定数量。

## 明确的委派边界

主 Agent 每次启动子代理前都会提交一份结构化任务合同，其中明确写出：

- 目标是什么，以及具体针对哪个仓库、目录、文件、模块、文档或其它对象。
- 必须做哪些工作，以及明确禁止做哪些工作。
- 子任务最多可以调用多少次工具、运行多长时间，以及其它限制。
- 子代理独立完成任务所需的事实、路径和材料。
- 最终需要返回什么、满足哪些条件才算完成、遇到什么情况必须停止并报告阻塞。

子代理看不到主对话，因此不会再依赖“结合前面内容”“看看这个项目”之类隐含上下文。对于仓库探索，主 Agent 必须先提供一个已知的绝对项目根目录；目录不存在、为空或目标子路径越出该根目录时，Cortex 会拒绝启动子代理并让主 Agent 修正，而不是让子代理向父目录或用户主目录盲目查找。

只读或可写权限由所选角色强制决定，不以合同中的自然语言为准。合同中的工具次数和执行时间也是实际运行限制；超过后只停止当前子任务，并保留已经得到的部分结果供主 Agent 接手。

1. 保持“使用现有代理”开启，让主 Agent 从已配置角色中选择；关闭后会改用一次性匿名角色。
2. 按机器资源设置“最大并行子代理数”；达到上限的新任务会等待空闲槽位。
3. 用“单个会话的子任务上限”限制一轮对话最多创建多少个子任务。
4. 需要更多专项角色时，打开“扩展代理”，再启用需要的角色。
5. 展开任意角色，可覆盖运行 Agent、模型、推理强度或追加提示词。Cortex 会话中的主 Agent 和子 Agent 都通过 Pi RPC 运行：Pi 角色可使用自己的模型覆盖；选择 Claude/Codex 角色时保留其角色设定，但执行会归一为 Pi 并继承父会话模型。Claude/Codex 主会话仍按其原有运行时执行子代理。
6. 需要自己的专项角色时，点击“新建子代理”，填写名称、职责、可用场景和工具权限后保存。自定义角色会立即进入主 Agent 的委派目录。

这些配置既可以从最右侧“子代理”面板快速修改，也可以在“设置 → 子代理”中集中管理；两处共享同一份配置并实时同步。设置页分为三个标签：

- “运行策略”设置是否使用现有代理、最大并行数和单轮子任务上限。
- “子代理配置”按工作表面、名称和分类查找角色，并在右侧详情栏调整 Agent、model、推理强度、追加提示词与启用状态；也可以创建、编辑或删除自定义角色。
- “自动模型角色”可单独配置代码审查和标题生成使用的 Agent、model 与推理强度。上下文压缩由 Pi 会话运行时管理；当前版本没有独立会话摘要任务，因此对应行只显示状态。

基础代理共 8 个，始终可用；扩展代理默认关闭，避免一次暴露过多不需要的委派入口。工作表面的“基础”表示所有场景可用；只选择 Code、写作或设计时，该角色只会出现在对应场景的委派目录。
标记为“只读”的审查与研究角色不会修改工作区，即使主会话当前允许编辑。

当 Cortex 会话权限设为“请求批准”时，普通聊天、Design/Slides 产物中的主 Agent 或任一子 Agent 调用 `bash`、`write`、`edit` 等写入/执行工具，都会在 Cortex 主窗口弹出确认框。确认框归属父会话；拒绝、停止本轮或关闭窗口都会阻止对应操作，自动委派和产物生成都不会绕过审批。

## 会话中的子代理卡

子代理开始执行后，会话中会出现一张任务卡，显示角色、状态、耗时、步骤数和最新活动：

- 探索卡片会显示中文“探索”和“代理 探索代理”，并标明实际运行模型；其他角色保留其配置名称。
- 点击卡片主体可展开或收起结论；标题、列表、表格、粗体等 Markdown 格式会正常渲染。
- 点击“预览”可在卡片旁优先查看子 Agent 的实际输出，最近步骤在下方作为补充；再次点击、按 `Esc` 或点击浮层外区域即可关闭。
- 点击“查看过程”会直接进入这一次委派对应的子会话。这里会保留委派任务和子 Agent 输出，不再另外显示“进入子会话”按钮。
- 子会话是只读过程页，底部不会显示输入框，而是显示“正在查看代理过程 / 返回主对话”状态条；需要继续提问时先返回主对话。

预览与结论不会同时展开；从预览进入过程页时，预览会自动关闭。子会话页会实时显示子 Agent 的思考与工具步骤（与主会话相同的过程时间线）；子任务结束后这份过程会自动存档，重启应用后进入子会话仍可回看思考、工具步骤和截断后的工具输入/输出。

如果单个子代理以相同参数得到相同工具错误 3 次，或者最近 8 次工具调用形成包含错误的重复循环，Cortex 会自动停止这一个子任务，避免继续消耗时间和 Token。任务卡会显示失败原因，并保留停止前已经产生的部分结果供主 Agent 接手；父会话、其他并行子代理和后续子任务不会被一起停止。

如果子代理达到本次任务合同约定的工具调用次数或执行时间上限，也会以同样方式只停止当前子任务。此时失败原因会明确显示为合同预算耗尽，便于主 Agent 缩小范围、补充材料或改为新的委派任务。

子会话不会出现在左侧普通会话列表或全局会话搜索中，避免把内部协作过程混成顶层对话。它始终从对应的父会话卡片进入；删除父会话时，对应子会话也会一起删除。

最终回答仍由主 Agent 根据当前会话上下文和子代理返回结果统一整理。子代理原始输出不会直接冒充最终回答。

# Cortex Desktop AI Slides Implementation Plan

> **For agentic workers:** 按任务顺序实施。每项功能先写失败测试，再写最小实现；涉及多个包时先固定类型和 IPC/MCP 契约。

**Goal:** 在 Cortex Desktop 的 Design Workspace 中实现 HTML-first AI Slides，支持提纲确认、逐页生成、应用内编辑检查，以及 PPTX/PDF/PNG/HTML 导出。

**Architecture:** 新增 `DesignDocument.kind = "slides"` 和独立 `SlidesDeckManifest`。每页是 `.cortex-design/<documentId>/slides/slot-*.html`，deck 元数据由 `deck.json` 管理。renderer 负责 UI，preload 只暴露窄 IPC，主进程负责文件、MCP、截图和导出。PPTX 采用复杂层栅格化与文本/图片/表格原生重建的混合管线。

**Tech Stack:** Electron 39、React 19、TypeScript、Zustand、Vitest、Testing Library、`@modelcontextprotocol/sdk`、Chrome DevTools Protocol、PptxGenJS、JSZip。

**Design Spec:** `docs/superpowers/specs/2026-07-16-ai-slides-design.md`

## 建议里程碑

### Milestone A：技术可行

- 完成 Task 0。
- 交付可编辑文本/图片/表格的 PPTX POC。

### Milestone B：内部可用

- 完成 Task 1–7。
- 能生成、恢复、排序、截图和检查 deck。
- 暂可只导出 PNG/PDF。

### Milestone C：MVP

- 完成 Task 8–10。
- 支持基本编辑和四种导出。
- 完成三 Agent 注入一致性与仓库外打包验证。

### Milestone D：增强

- 完成 Task 11。
- 模板、备注、多 Agent review 和更高保真转换。

## 实施纪律

- 不把 Slides 状态塞进现有 `DesignArtifactNode` 或自由画布投影。
- 不允许 renderer 直接读写 deck 文件。
- 不为导出开放通用 debugger IPC。
- 不先做完整 UI 再验证 PPTX；Task 0 是硬门槛。
- 每个新主进程依赖都必须完成打包态、asar 和仓库外启动验证。
- 每个跨进程类型改动都同步更新镜像契约测试。
- 每个工具写入都必须有路径校验、revision 和原子落盘。
- 保留用户工作区已有改动；按任务拆小提交，避免一次提交横跨全部里程碑。

# 个人工作区左侧栏“项目上下文”重构设计

## 背景

当前个人工作区左侧栏同时平铺会话、写作、项目管理、闪记、自动化、Loop 工作流、项目树、设计和设置。功能完整，但顶层入口与项目/会话内容处于相近的视觉权重，项目树较长时底部入口容易离开视线，用户难以快速判断“当前正在处理哪个项目”。

本次重构采用已确认的 C 方案“项目上下文”：左侧栏围绕当前项目组织会话和项目切换，将跨项目工具收敛为始终可见的固定底部入口。

## 目标

1. 让用户一眼识别当前工作模式、当前项目和当前会话。
2. 建立清晰层级：工作模式 → 当前项目 → 当前项目会话 → 项目切换 → 全局快捷入口。
3. 保留现有功能能力，不改变数据模型、持久化结构或桌面桥接契约。
4. 项目和会话数量增多时，设置与常用工具仍始终可见。
5. 延续主界面的柔和、轻量风格，减少现有侧栏的平铺感和视觉噪声。

## 非目标

- 不修改会话、项目、归档、自动化、Loop、闪记等业务逻辑。
- 不新增路由、IPC、Zustand 状态或持久化字段。
- 不重做中栏、右栏、标题栏或设置弹层。
- 不改变侧栏默认宽度和折叠侧栏机制。

## 信息架构

侧栏由五个纵向区域构成：

1. **窗口控制区**：保留现有折叠侧栏与搜索控制，以及 macOS 红绿灯让位规则。
2. **工作模式切换**：使用三段式控件呈现“会话 / 写作 / 设计”。当前模式使用浅色实底、轻描边或阴影表达选中状态。
3. **当前项目卡片**：显示当前项目名称和“当前项目”标签；提供“新建会话”主操作与“项目管理”次操作。
4. **可滚动内容区**：先显示当前项目的会话，再显示项目切换列表；只有该区域滚动。
5. **固定快捷入口区**：横向四等分显示“闪记 / 自动化 / Loop / 设置”，固定在侧栏底部，不随内容滚动。

视觉顺序如下：

```text
窗口控制
会话 | 写作 | 设计
┌ 当前项目 ─────────┐
│ 新建会话  项目管理 │
└───────────────────┘
当前项目会话
  会话 A
  会话 B
切换项目
  项目 B
  项目 C
  无项目
──────── 可滚动区结束 ────────
快捷入口
闪记 | 自动化 | Loop | 设置
```

## 组件调整

### 工作模式切换

- 由现有顶部入口重新组合为“会话 / 写作 / 设计”。
- “会话”继续调用 `openHome`，“写作”继续调用 `openWriting`，“设计”继续调用 `openDesign`。
- 缺少桌面桥接能力时，沿用当前能力门控；不可用模式不渲染，剩余模式等宽分布。
- 选中态分别由 `homeOpen`、`writingOpen`、`designOpen` 驱动，不引入重复状态。

### 当前项目卡片

- 有活动项目时显示项目名和“当前项目”标签。
- “新建会话”沿用当前默认 Agent 解析逻辑，在当前项目下创建会话。
- “项目管理”沿用 `onOpenProjectsWindow` 和 `bridge.tasksListProjects` 双门控。
- 当前上下文为“无项目”时，卡片标题显示“无项目会话”；主操作创建无项目会话。
- 尚未选择项目或会话时，卡片显示“选择一个项目开始”，主操作仍允许创建无项目会话，次操作打开项目管理。

### 当前项目会话

- 只显示当前上下文中的未归档会话，按 `updatedAt` 降序。
- 会话选中、时间显示、归档和删除能力继续复用现有 `SessionRow` 行为。
- 超过 5 条时继续复用 `SessionList` 的展开/折叠逻辑。
- 没有会话时显示轻量空状态，并提供与卡片主操作一致的“新建会话”提示。

### 项目切换列表

- 显示未归档项目，当前项目不重复出现在列表中。
- 点击项目后沿用现有项目激活规则：优先打开最近会话；无会话时进入项目引导态。
- 保留添加项目入口。
- “无项目”作为伪项目入口显示；存在无项目会话时可切换进入该上下文。
- 已归档项目保留为默认折叠分组，展开后仍可访问和管理。
- 项目行的更多、归档会话显示与新建 Session 操作继续沿用现有菜单与能力，默认收敛到悬停操作区。

### 固定快捷入口

- 固定于侧栏底部，位于独立的半透明或实色工具面板中。
- 四个入口分别为闪记、自动化、Loop、设置。
- 闪记、自动化、Loop 继续按各自桥接能力决定是否渲染；设置始终渲染。
- 能力缺失时，剩余入口自动等宽填充，不保留空槽。
- 当前打开自动化或 Loop 时，对应入口使用明确选中态；设置弹层打开时设置入口使用选中态。

## 视觉规范

- 复用 `--bg-sidebar`、`--bg-app`、`--bg-hover`、`--bg-active`、`--border`、`--text-*` 和 `--accent`，不增加硬编码主题色体系。
- 当前项目卡片使用比侧栏背景高一层的表面色、细边框和轻阴影，不使用强渐变或大面积高饱和紫色。
- 紫色强调仅用于主操作、当前模式或当前会话的少量状态提示。
- 项目、会话和快捷入口统一使用 8–10px 圆角；避免每一行都变成独立厚重卡片。
- 文字层级：项目名 13px/600，会话 12.5px/400–500，分组标签 10–10.5px/600，辅助时间 11px。
- 当前会话使用浅底色与左侧 3px 强调线；悬停仅提升背景和文字对比度。
- 底部快捷入口至少 36px 高，图标与文字垂直排列或紧凑横排，保证 288px 侧栏下仍有清晰点击区域。

## 滚动与布局

- `aside.sidebar` 保持纵向 flex 布局和现有宽度。
- 顶部控制、模式切换、项目卡片和底部快捷入口均 `flex-shrink: 0`。
- 中间内容区使用 `flex: 1; min-height: 0; overflow-y: auto`。
- 底部工具区通过自身背景、顶部细分隔线与轻微 `backdrop-filter` 和内容区区分。
- 在侧栏高度不足时，优先保证窗口控制、模式切换和底部快捷入口可见；项目卡片和内容区内部保持紧凑。

## 交互与状态

- 保留所有现有 hover、active、disabled、归档和二次删除确认行为。
- 所有按钮保留 `title` 或可访问名称；仅图标按钮不得依赖图形本身传达含义。
- 键盘焦点使用 `:focus-visible` 明确显示，颜色对比至少达到现有应用控件水平。
- 动画仅使用 120–180ms 的颜色、透明度和位移过渡，并遵守 `prefers-reduced-motion`。
- 项目或桥接数据尚未就绪时不显示虚假内容，使用现有能力门控和真实空状态。

## 实现边界

主要修改范围：

- `packages/views/cortex-desktop/personal/PersonalSidebar.tsx`
- `packages/views/cortex-desktop/cortex-desktop.css`
- `packages/views/cortex-desktop/personal/PersonalSidebar.test.tsx`

如拆分后能显著降低 `PersonalSidebar.tsx` 的职责，可在同目录新增纯展示组件，但不迁移 store 或桥接逻辑，不做无关重构。

## 验证方案

### 组件测试

- 三种工作模式的渲染、能力门控和点击回调正确。
- 当前项目卡片显示正确项目，并将新会话创建到正确上下文。
- 项目切换列表不重复当前项目，且保留无项目与归档入口。
- 固定快捷入口按桥接能力显示，设置始终存在。
- 会话归档、删除、展开折叠等既有交互不回归。

### 静态验证

- 运行 `pnpm --filter @cortex-work/views test -- PersonalSidebar.test.tsx`。
- 运行 `pnpm --filter @cortex-work/views typecheck`。
- 运行相关 ESLint 命令和 `git diff --check`。

### 界面验收

- 在 macOS 桌面端验证正常高度与较矮窗口。
- 验证 0 个项目、多个项目、长项目名、超过 5 个会话、有无归档项目等状态。
- 验证底部四个入口始终可见，内容滚动不推动底部工具区。
- 验证浅色、深色及现有调色板下的对比度和层次感。
- 验证侧栏折叠、恢复及原生标题栏红绿灯对齐不回归。

## 验收标准

1. 用户无需滚动即可看到当前模式、当前项目和设置入口。
2. 侧栏主体只强调一个当前项目与一个当前会话，不出现多个同权重主焦点。
3. 项目和会话增加时，仅中间内容区滚动。
4. 现有入口、能力门控和会话/项目操作均可达。
5. UI 与主界面的柔和浅色表面、圆角和紫色强调保持一致，且不依赖新增业务状态。
